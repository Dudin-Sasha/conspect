### Предметно ориентированное проектирование *DDD*

Подход к разработке ПО, при котором архитектура и внутренняя структура приложения строятся вокруг предметной области и её бизнес правил (намного сложнее MVVM)

Основная идея DDD заключается в том что разработчик должен сначала разобраться в деятельности организации для которой, создается ПО, а уже за тем переходить к проектированию.
#### Главный принцип DDD 
Программная модель должна отражать реальные процессы и ограничения предметной области 

# Предметная область (Domain)

Domain - это предметная область то есть определённая сфера деятельности, для которой разрабатывается ПО


| Система          | Предметная область      |
| ---------------- | ----------------------- |
| Интернет магазин | Продажа                 |
| Банки            | Денежные операции       |
| Склады           | Логистика               |
| Доставка         | Логистика               |
| Бронирование     | Резервирование ресурсов |

При проектировании необходимо выяснить какие процессы существуют в организации, кто в них участвует, какие данные используются, и какие существуют ограничения выполнения операций.


## Domain Model - Доменная модель

Доменная модель - это программное представление предметной области, включающая её основные понятия отношения между ними, поведение и бизнес правила

#### Система управления складом:
- Товар,
- склад,
- место хранения,
- остаток ,
- партия,
- перемещение,
- списание,
- инвентаризация

"В базе данных структура не обязана полностью совпадать с доменной моделью"

## Стратегическое проектирование (СП)

СП - используется для определения общей структуры, предметной области и выделения её основных частей

#### Основные понятия СП:
- subdomain - поддомен,
- coredomain - основной поддомен,
- supporting subdomain - вспомогательные поддомен,
- generic subdomain - типовой поддомен,
- bounded context - ограниченный контекст,
- context map - карта контекста

### Subdomains - Поддомены

Поддомен - это логически выделенная часть предметной области отвечающая за одну бизнес функцию.

```Пример
Интернет-магазин:
- управление каталогом товаров
- управление продажами
- обработка платежей
- организация доставки
```


## Core Domain

core domain - конкурентное преимущество организации

Например для логистической компании основным доменом может быть система оптимизации маршрутов доставки
для интернет магазина - механизм формирования персональных предложений

## Supporting subdomain

Supporting subdomain - часть системы которая поддерживает основную деятельность организации, но сама по себе не является главным конкурентным преимуществом

Например: управление внутренними заявками, учет оборудования, обработка возвратов

## Generic subdomain 

generic subdomain - распространённая (типовая) функциональность ПО

Например: аутентификация пользователей, отправка писем, хранение файлов, базовое логирование, генерация документов.

Для таких задач уже существуют готовые (не нужна собственная реализация)


# Ubiquitous language - Единый язык

Единый язык - согласованная система терминов, которая используется разработчиками и экспертами предметной области, при обсуждении и реализации ПО. 

"Резервирование продукта в случае ДДД это одно и тоже определение и для программиста и для другого человека"


# Проблема неоднозначности термина

Клиент/Customer - рамках интернет магазина может означать владельца учетной записи, или человек который оплатил заказ, или получатель товара, или организацию

Глоссарий

| Термин  | Определение                                        |
| ------- | -------------------------------------------------- |
| Товар   | Объект доступный для продажи                       |
| Остаток | Учётное количество товаров                         |
| Резерв  | Количество товара временно закреплённое за заказом |

## Bounded context - Ограниченный контекст

Ограниченный контекст - это контекст внутри которого существует определённая доменная модель и действует согласованный глоссарий 

## Context map - карта контекста

Когда система состоит из нескольких ограниченный контекстов, необходимо определить как они взаимодействуют, для этого используется context map. Она описывает отношения между контекстами, направления зависимостей и способы передачи информации
